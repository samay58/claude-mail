**Problem**: Email detail view displayed raw HTML tags and CSS instead of readable content.

**Root Cause Analysis**:
- Email `BodyText` field contained HTML markup from server
- Glamour markdown renderer expects plain text, not HTML
- No HTML stripping before rendering
- User saw: `<div style="font-family: Arial">...` instead of email content

**Solution Implemented**:
```go
// internal/ui/preview/preview.go
// 1. Added HTML stripping function (30 lines)
func stripHTML(input string) string {
    // Strip <script> and <style> tags with content
    scriptRe := regexp.MustCompile(`(?i)<script[^>]*>[\s\S]*?</script>`)
    input = scriptRe.ReplaceAllString(input, "")

    // Strip all HTML tags
    tagRe := regexp.MustCompile(`<[^>]*>`)
    input = tagRe.ReplaceAllString(input, " ")

    // Decode HTML entities (&nbsp; → space, &amp; → &)
    input = html.UnescapeString(input)

    // Clean up whitespace
    spaceRe := regexp.MustCompile(`\s+`)
    input = spaceRe.ReplaceAllString(input, " ")

    return strings.TrimSpace(input)
}

// 2. Applied stripping in renderEmail()
content := m.email.Markdown
if content == "" {
    content = stripHTML(m.email.BodyText) // Clean HTML
}
```

## 🎓 Key Learnings

### 1. Event Priority Architecture in Bubble Tea
**Challenge**: Global keyboard shortcuts conflicted with component-specific handling

**Learning**: Event handler priority matters!
```
Priority Order (top to bottom):
1. Overlays (help, search) - most specific
2. View-specific (compose, detail) - context-aware
3. Global navigation (g, i, l, p) - fallback only
```

**Pattern Identified**:
```go
// Anti-pattern: ❌
case "key":
    doSomething()
    return m, nil  // Blocks all components

// Correct: ✅
case "key":
    if specificContext {
        doSomething()
        return m, nil
    }
    // Fall through to components
```

**Application**: Always check context (view state, overlays) before handling global shortcuts.

---

### 2. HTML Content in Email Applications
**Challenge**: Email bodies contain rich HTML, but TUIs need plain text

**Solution Strategy**:
1. Strip `<script>` and `<style>` tags first (prevent display of code)
2. Remove all remaining HTML tags (keep structure)
3. Decode HTML entities (`&nbsp;` → space)
4. Normalize whitespace (collapse multiple spaces)

**Regex Patterns Used**:
```go
scriptRe := regexp.MustCompile(`(?i)<script[^>]*>[\s\S]*?</script>`)
styleRe := regexp.MustCompile(`(?i)<style[^>]*>[\s\S]*?</style>`)
tagRe := regexp.MustCompile(`<[^>]*>`)
spaceRe := regexp.MustCompile(`\s+`)
```

**Why This Works**: Progressive stripping from most dangerous (scripts) to least (tags) to formatting (whitespace).

---

### 3. Message Passing in Bubble Tea
**Challenge**: Components send close messages but app doesn't receive them

**Root Cause**: Global handler returns early, never reaching message switch

**Fix**: Use `break` instead of `return` to fall through to component updates:
```go
// Before: ❌
case "esc":
    handleViewNavigation()
    return m, nil  // CloseHelpMsg never processed

// After: ✅
case "esc":
    if overlay {
        break  // Fall through to process CloseHelpMsg
    }
    handleViewNavigation()
    return m, nil
```

**Lesson**: `break` continues message flow, `return` stops it.

---

### 4. Debugging Bubble Tea Applications
**Effective Debugging Process**:
1. **User Reports Issue**: "Can't type 'i' in compose"
2. **Reproduce Locally**: Verify exact behavior
3. **Trace Event Flow**: Where does 'i' key go?
   - Check global handlers first (app.go)
   - Check component handlers (compose.go)
4. **Identify Blocker**: Global `case "i"` returns early
5. **Add Context Check**: `if m.view != "compose"`
6. **Verify Fix**: Test in both contexts (list vs compose)

**Tools Used**:
- `grep` to find all handlers for a key
- Code reading to trace message flow
- Build testing to verify compilation

### **Sprint 3: MEDIUM Priority Fixes** (2 hours)

#### Fix 3.1: IMAP Reconnection Logic ⭐⭐
**Problem**: "IMAP not connected" errors after app runs for extended periods. Connection drops unexpectedly.

**Root Cause Analysis**:
- `imap.ts` line 213 called `disconnect()` in finally block after every operation
- No reconnection logic when connection times out or drops
- Connection state not tracked - couldn't detect disconnections
- `getRecentEmails()` reconnected from scratch each time (expensive)

**Solution Implemented**:
```typescript
// email-agent/src/imap.ts - Connection State Management

// Added connection state enum (lines 20-27)
enum ConnectionState {
  DISCONNECTED = 'disconnected',
  CONNECTING = 'connecting',
  CONNECTED = 'connected',
  RECONNECTING = 'reconnecting',
  ERROR = 'error'
}

// Added state tracking fields (lines 34-39)
private connectionState: ConnectionState = ConnectionState.DISCONNECTED;
private reconnectAttempts: number = 0;
private maxReconnectAttempts: number = 5;
private reconnectTimer: NodeJS.Timeout | null = null;
private lastConnectionError: Error | null = null;

// Enhanced connect() with persistent error handlers (lines 85-119)
this.imap.on('error', (err: Error) => {
  console.error('[IMAP] Runtime error:', err.message);
  this.connectionState = ConnectionState.ERROR;
  this.lastConnectionError = err;
  this.scheduleReconnect();  // Auto-reconnect on errors
});

this.imap.on('end', () => {
  console.log('[IMAP] Connection ended');
  if (this.connectionState === ConnectionState.CONNECTED) {
    // Unexpected disconnect - schedule reconnection
    this.connectionState = ConnectionState.DISCONNECTED;
    this.scheduleReconnect();
  }
});

// Added exponential backoff reconnection (lines 283-300)
private scheduleReconnect(): void {
  if (this.reconnectTimer || this.reconnectAttempts >= this.maxReconnectAttempts) {
    return;
  }

  const delay = Math.min(1000 * Math.pow(2, this.reconnectAttempts), 30000);
  this.reconnectAttempts++;

  console.log(`[IMAP] Scheduling reconnect attempt ${this.reconnectAttempts}/${this.maxReconnectAttempts} in ${delay}ms`);

  this.reconnectTimer = setTimeout(() => {
    this.reconnect();
  }, delay);
}

// Added ensureConnected() guard (lines 333-349)
private async ensureConnected(): Promise<void> {
  if (this.connectionState === ConnectionState.CONNECTED && this.imap && this.imap.state === 'authenticated') {
    return;  // Already connected
  }

  if (this.connectionState === ConnectionState.CONNECTING || this.connectionState === ConnectionState.RECONNECTING) {
    await new Promise(resolve => setTimeout(resolve, 1000));
    return this.ensureConnected();  // Wait and retry
  }

  if (this.connectionState === ConnectionState.DISCONNECTED || this.connectionState === ConnectionState.ERROR) {
    await this.connect();
  }
}

// Modified getRecentEmails() to keep connection alive (lines 237-265)
async getRecentEmails(days = 7, limit = 150): Promise<ParsedEmail[]> {
  try {
    await this.ensureConnected();  // Use guard instead of connect()
    await this.openBox('INBOX', true);
    // ... fetch logic ...
    return emails.sort((a, b) => b.date.getTime() - a.date.getTime());
  } catch (error) {
    console.error('Email fetch failed:', error);
    throw error;
  }
  // REMOVED: finally { this.disconnect(); }
  // Connection now stays alive for reuse
}
```

**Files Modified**:
- `email-agent/src/imap.ts` (+140 lines)

**Key Learning**: **Keep connections alive, don't disconnect after operations**. Persistent connections with auto-reconnection are more reliable than connect/disconnect cycles. Exponential backoff prevents server hammering.

## 🎓 Highest Priority Learnings (Ultrathink Summary)

### Technical Principles
1. **Persistent Connections are Reliable**: Don't disconnect after every operation
2. **State Transitions Need Explicit Cleanup**: Add `Reset()` methods, force re-renders
3. **Context is King**: Check view state before processing global events
4. **Background Operations Delight Users**: Async + progress logging = better UX

### Process Insights
1. **Sprint-based fixes** manage complexity better than big-bang approaches
2. **Root cause analysis** before coding prevents wrong solutions
3. **Immediate documentation** preserves details while context is fresh
4. **Zero-error policy** (compile after each change) prevents bug accumulation

### Design Wisdom
1. **Persistent > Ephemeral** (connections, state)
2. **Explicit > Implicit** (cleanup, resets)
3. **Proactive > Reactive** (auto-reconnect, auto-prioritize)
4. **Async > Blocking** (background processing, progress feedback)
